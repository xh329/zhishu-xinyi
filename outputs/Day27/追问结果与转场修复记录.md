## 二、这条回答里藏着一个产品发现（比修复更重要）

**同一本书收两次，用户自己发明了正确用法：把同一本书当作"不同时间段的不同阅读"。**

- 佐证：书架 2 本《非暴力沟通》+ 心迹 2 段心得（分别对应两次阅读）。
- 结论：**"收书无重复提醒"不是 bug，是 feature** —— 我昨天记的"待确认观察"就此关闭，**不要**加"这本书已在架上"的拦截。
- 产品含义（记下，今天不做）：将来若做"同一本书的多轮阅读"，正确的形态是"一本书下挂多次阅读记录"，而不是禁止重复收书。这正是"真实用户教会你从没想过的事"——今天课程主题的答案之一。

## 三、定级与修复：画面转换（真人指定，P1）

**为什么这次是真 P1**：真人明确说"最别扭 + 只改一处改这里" + 会用第二次（会反复经历这个转换）→ 影响所有人、高频触发、不挡流程。

**实拍诊断**（`shots/转换-before-*.png`，不靠读代码下结论）+ 代码核对，找到三个具体病灶：

1. 全站进场动画**时长不一**：0.8s / 0.9s / 1.1s / 1.2s / 1.4s / 1.6s / 1.9s 混用 → 每次切换"忽快忽慢"。
2. 整块内容**同时浮现**（容器一个 fadein 包住一切）→ 没有层次，视线没有落点。
3. SPA 视图切换（`showView`）与跨页跳转是两套节奏 → 转换语言不统一。

**修复（CSS-only，不碰任何 HTML 结构 / JS 逻辑 / 布局）**：

- 全站统一 `page-in`（0.45s、上移 8px）替代原 7 种时长。
- **两级错开**：`.viewbar`（位置行）0s 先落定 → 内容块每层 +0.07s → 视图内容永远比位置行晚一拍（先知道自己在哪，再看内容）。
- `.whisper`（诗意低语）最后一个到（+4 拍）——保留它"最后浮现"的气质，但纳入统一节奏。
- `prefers-reduced-motion` 同步全部关闭（无障碍不破）。
