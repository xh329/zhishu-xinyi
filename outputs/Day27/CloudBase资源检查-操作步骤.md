## 零、先做这一步：这个环境还在吗（30 秒）

**为什么先做**：本项目 Day 20 起接的 CloudBase 公网接口已经死了。实测证据：

```bash
curl -s -o /dev/null -w "[HTTP %{http_code}]\n" -m 15 \
  https://zhishu-xinyi.apigw.tencentcs.com/release/api/health
# 实测结果：[HTTP 000]  ← 000 = 连 DNS 都解析不到，不是"接口报错"
```

| 判定 | 现象 | 含义 |
|---|---|---|
| **环境已回收** | 控制台「云开发」里看不到 `zhishu-xinyi` 这个环境；或能看到但状态为"已销毁/已删除" | 写入 `资源与到期说明.md` 的结论栏即可，**不用再查额度**（没有额度可查） |
| **环境还在** | 能看到环境、状态正常 | 继续往下走，逐项查用量与到期 |

> 说明：`zhishu-xinyi.apigw.tencentcs.com` 的 DNS 不通，**不等于**环境一定没了（域名可能只是单独被回收）。**以控制台看到的为准**，别用 curl 的结果直接下结论。

## 二、查用量（"现在用了多少"）

| 步 | 操作 | 记录什么 |
|---|---|---|
| 2.1 | 环境 → 「**资源与配额 / 用量**」 | **本月**各资源用量：云函数调用次数、数据库读写次数、存储容量、CDN/流量、静态托管流量 |
| 2.2 | 同一页找「**资源包**」或「**额度**」 | 免费额度 / 已购资源包的**剩余量**、**已用百分比** |
| 2.3 | 「**计费**」 → 账单概览 | 计费模式（免费额度 / 按量付费 / 包年包月）、**是否欠费** |
| 2.4 | 环境详情 / 套餐页 | **到期时间**（免费环境无到期日，写"免费额度版，无到期日"，别硬编一个日期） |

**必须抄下来的四个数**（填 `资源与到期说明.md`）：
① 本月用量（挑最要紧的 2–3 项写，别抄一屏）② 剩余额度 ③ 到期日期 ④ 是否欠费。

## 三、导出数据（历史后端里到底有没有数据）

> ⚠️ **先说清楚一件事，别白忙**：本项目的用户数据**现在不在云上**，在**浏览器 `localStorage`** 里（Day 20 之后数据层已切回本地）。所以"导出数据"要分清导的是哪一堆。

| 要导的 | 在哪 | 怎么导 | 有没有 |
|---|---|---|---|
| **A. CloudBase 数据库**（`books` / `notes` 表，Day 16–22 期间写入过的） | 云开发控制台 → 数据库 | 见下面 3.1 | 环境若已回收 → **无**；还在 → 看表里有没有行 |
| **B. 现在线上的用户数据** | 用户的浏览器 `localStorage`（键前缀 `zhishu_`） | 浏览器 F12 → Application → Local Storage → 复制 `zhishu_books` / `zhishu_notes` 的值；或控制台执行 `copy(localStorage.getItem('zhishu_notes'))` | 有（就是你试用时写进去的那些） |

**3.1 导出 CloudBase 数据库（若环境还在）**

| 步 | 操作 |
|---|---|
| 3.1.1 | 控制台 → 该环境 → 「**数据库**」 |
| 3.1.2 | 找到 `books`、`notes` 集合，先看**条数**（0 条就写"无数据，无需导出"） |
| 3.1.3 | 选中集合 → 「**导出**」→ 选 JSON（保留结构）或 CSV（好读）→ 下载 |
| 3.1.4 | 把导出文件放 `outputs/Day27/导出数据/`，**文件名带上日期** |
| 3.1.5 | 在 `资源与到期说明.md` 里登记：**文件名 + 条数 + 导出时间**（不贴内容） |

> 若控制台没有导出按钮，用命令行：本机装 `@cloudbase/cli` 后 `tcb login` → `tcb db export`（**登录凭据别截图、别写进仓库**）。

**3.2 导出浏览器里的数据（这个才是"现在真正在用的数据"）**

| 步 | 操作 |
|---|---|
| 3.2.1 | 浏览器打开 `https://zhishu-xinyi-70127.app.workbuddy.host/`，走一遍刚才试用时写的书/心得 |
| 3.2.2 | F12 → Console → 执行 `copy(localStorage.getItem('zhishu_books'))`，粘到文件里存好 |
| 3.2.3 | 同理 `zhishu_notes` |
| 3.2.4 | 存 `outputs/Day27/导出数据/browser-books-2026-10-13.json`、`browser-notes-2026-10-13.json` |

> **这就是"数据只存在本地"这条已知边界的实证**：换一台设备打开同一条链接 → 数据是空的。今天顺手把它拍下来，作为"资源与数据到底在哪"的说明。
