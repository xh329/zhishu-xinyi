## 三、动作 2：导航图（只走页面上的链接）

以首页为起点，把所有**页面上看得见、点得到**的去处列全：

```
首页 index.html（#/home）
├─ 顶部导航 ── 今日 / 书架 / 心迹
├─ 「开始今天的阅读」───────────→ book.html（收下一本书）
├─ 「去书架看看」───────────────→ #/books
│
book.html（收下一本书）
├─ 提交后出现「写几句心得」─────→ note.html（写心得）
├─ 「回到今日」→ index.html#/home ／「看看书架」→ index.html#/books
│
note.html（写几句心得）
├─ 「温柔留存」= 保存
├─ 「先不放进去（撤销）」= 1.6 秒内可反悔
├─ 「再收一本书」→ book.html ／「我的心迹」→ index.html#/notes
│
notes.html（我的心得）
├─ 「筛一筛」输入框（按书名/关键字过滤）
├─ 空状态时「收下第一本书」→ book.html
└─ 「回到今日」→ index.html#/home ／「看看书架」→ index.html#/books

检查台 check.html ← ❌ 以上任何页面都没有通向它的链接
```

**关键发现**：把全部页面上的可点元素数完一遍，**没有一条路径能把人带到"修改"或"删除"**。
`check.html` 这个页面在**源码、文档、演示提纲**里被引用了 30 多次，**唯独在 UI 上没有任何入口**。

## 四、动作 3：只有作者知道的东西

| 只有你知道 | 页面上有没有线索 | 真人会怎么反应 |
|---|---|---|
| 改心得 = 打开 `check.html` 第 ⑤ 块 | ❌ 无 | 在"心迹"列表上长按/左右滑/找三点菜单 |
| 删心得 = 打开 `check.html` 第 ⑥ 块 | ❌ 无 | 同上，然后放弃 |
| `check.html` 需要**手动拼 URL** 才进得去 | ❌ 无 | —— |
| 「温柔留存」= 保存按钮 | ⚠️ 只有这一个按钮在正文下方，靠位置猜 | 可能犹豫 2–10 秒 |
| 数据存在**他自己的浏览器**里（换设备就没了） | ❌ 无 | 多半不会想到，也不会因此受挫 |

## 五、预测卡点（**待真人证实**）

| 预测编号 | 预测卡点 | 预测步骤 | 预测严重度 | 它的判定标准（真人试用时怎么算命中） |
|---|---|---|---|---|
| **K-预1** | **「修改 / 删除」在界面上完全找不到入口**（只存在于开发者自检页 `check.html`，且该页无导航入口、文案全是"接口/PATCH/第 7 项"） | 第 5、6 步 | **P0** | 真人在第 5 步 ≥ 60 秒仍未找到、或直接说"能改吗？" → **命中** |
| **K-预2** | **「温柔留存」四个字不自解释**：诗意的命名盖住了"保存"这个动作 | 第 3 步 | P1 | 真人第 3 步停顿、来回看、或问"哪个是保存" → 命中 |
| **K-预3** | **对外链接有两条、内容不同**（`zhishu-xinyi-70127.…` = v1.0 可复现；`zhishu-xinyi.…` = Day26 记录的旧内容、发布源不在仓库里） | 第 0 步 | P2（口径问题） | 不影响对方操作（两版功能一致，实测 6 个 `<h3>` 块齐全），但**会让你的截图证据说不清是哪一版** → 属于"发之前先统一口径" |

### 补充发现（预判的第二层问题，今天不一定修）

即使真人**误打误撞**进了 `check.html`，"删除"也**删的不是他刚才那条**：

> 页面原话是「**删除列表里最新一段**」—— 按钮的语义是"最新"，而第 6 步里真人的意图是"删掉我刚改的那条"。**意图与动作对不上**，删错了他也不知道。

同类问题：`check.html` 第 ⑤ 块是"取列表里最新的一段心事"来改 —— 同样不是"用户想改的那条"。
这说明 **改/删这两个能力，目前是"面向自检"实现的，不是"面向用户"实现的**。真人试用的第 5、6 步，测的正是这个落差。
