## 零、开场话（30 秒，照念，别多说）

> 「帮我试个东西，两三分钟就行。这是一个写读书心得的网站。
> 我没有说明书，你就当第一次见到它，自己摸索着来。
> 遇到不知道点哪，**直接说出来**就好 —— 卡住不是你的问题，是我要的东西。
> 全程我不会帮你点，也不会告诉你下一步在哪。」

**四件不能说的事**（说完这次试用就白做了）：

| 不能说 | 为什么 |
|---|---|
| 别提这是课程作业 / 我自己做的 | 一提"帮朋友测试"，对方就开始替你找补、舍不得说难听 |
| 别告诉他数据存在浏览器里 | 第 4、7 步测的就是"他以为数据会丢吗、会不会真丢" |
| 别告诉他「修改 / 删除」在检查台 | 第 5、6 步是整个试用的核心探测点，说了一分不得 |
| 别念「温柔留存就是保存按钮」 | 第 3 步的含糊点，测的是"按钮名字看不看得懂" |

## 一、任务卡（对方照做 · 7 步）

链路：**打开链接 → 看到核心数据 → 完成一次核心操作 → 刷新确认 → 修改 → 删除**

| # | 让对方做什么（**只说"点什么"**） | 卡住时怎么记 |
|---|---|---|
| **0** | 在**你自己的手机**上打开这条链接：`https://zhishu-xinyi-70127.app.workbuddy.host/` | 打不开 → 记下浏览器、报错原话、截图（这条一卡，后面全废） |
| **1** | 首页停 5 秒，然后告诉我：你觉得这个网站是**干嘛的**？ | 说不出/说错 → 记原话。**这问的是"看懂了吗"，不是操作** |
| **2** | 点「**开始今天的阅读**」。随便写一本你正在读、或想读的书，**把它收下**。 | 记第一次犹豫、误点、来回切页 |
| **3** | 接着写三句话：读完这本书你有什么感觉。顺手点一个心情。写完，**把它存起来**。 | ⚠️ **含糊点①**：**不要**说出「温柔留存」这四个字，也不要指哪个是保存键。记他花了多久找到 / 他找的时候嘴里念什么 |
| **4** | **刷新一下页面**（下拉或 F5）。刚才写的东西**还在吗**？ | 不在 → 立刻截图。**这条最致命，等于数据是假的** |
| **5** | 把刚才那条心得**改一改**，随便改一个字都行。 | ⚠️ **含糊点②**：**不说在哪改**。这是本次试用的核心探测点。记他第几秒开始乱点、第几秒放弃、放弃前说了什么 |
| **6** | 把它**删掉**。 | 同样只说这一句。他若问"这也能删吗"，答「你试试看」 |
| **7** | 最后**再刷新一次**，看你删掉的那条**还回不回来**。 | 回来了 → 截图（说明"删除"没有真正落盘） |

**计时**：第 0 步开始计时，第 7 步结束停表。**总用时填进记录表**（外行跑通一遍应该 < 3 分钟；超过 5 分钟本身就是一条 P1 反馈）。

## 二、被故意写含糊的两处（主持人须知，**别念出来**）

| 位置 | 呈现给对方的原话 | 真实答案 | 测的是什么 |
|---|---|---|---|
| 第 3 步 | 「把它**存起来**」 | 点页面上那个 **「温柔留存」** 按钮 | **按钮命名能不能自解释**。若对方找不到，说明"温柔留存"诗意太重、动作不明 —— 这是**文案问题，不是对方笨** |
| 第 5 步 | 「把它**改一改**」 | 只能去 **`check.html`（检查台）** 的第 ⑤ 块 | **改/删的入口有没有被藏起来**。检查台在任何页面导航里**都没有入口**，而且里面全是"接口""PATCH""第 7 项"这类开发者词 |

> 这两处是**故意留白**，用来逼出真实卡点。**第 5 步大概率就是今天要修的那条** —— 预测依据见 `预检-代理试跑记录.md`。

## 三、观察纪律（照做，别好心）

1. **手别上**。对方的鼠标/手指停在哪、来回点几次，全部如实记。
2. **嘴别答**。只重复他的问题（"在哪改呢？"→"你觉得会在哪？"），不要给答案。
3. **卡住超过 90 秒**就喊停，记下"停在这一步、卡了 90 秒、他找过的地方有：___"。**不要在卡住之后继续往下做**，后面的步骤已经失去意义。
4. **原话优先**。记他的原句（"这个…收下是啥意思"），不要润色成"他认为按钮语义不清"。
5. **截图时机**：①第 4 步刷新后的画面 ②第 5 步卡住时的画面（停在哪个页面）③第 6 步删除后的画面 ④第 7 步刷新后的画面。**截图要带地址栏/状态栏**，能看出是手机上、是哪个页面。

## 五、记录怎么填

打开 `试用记录表模板.md`，按表逐格填。**七个字段一个都别省**：

- **对方**（谁 / 什么设备 / 什么浏览器）—— 决定这条反馈的适用范围
- **本步结果**（✅ 顺利 / ⚠️ 犹豫后做到 / ❌ 没做到）
- **卡住的原话**（机器不能替的，就是这栏）
- **花了多久**（超过 90 秒的步骤标红）
- **他尝试过的路径**（点过哪些地方 —— 这是修 UI 入口的直接依据）
- **截图编号**（与 `Day27-*-*.png` 对应）
- **是否中断**（中断就说明后面没测）

填完把表发回来，我按 `卡点优先级-判定与修复提示词.md` 选最高优先级、出修复提示词和复验任务。

## 六、卡住降级（今天没找到人时用）

> **触发条件**：今天联系不上第三方，或对方临时没空。

按课程给的口径执行：

1. **间隔 10 分钟**（不是立刻 —— 立刻重做会带着刚看过的记忆，测不出"第一次"）。
2. 按上面 7 步**重新走一遍**，但这次**当作自己从没打开过本站**：
   - 换一个**从没用过的浏览器**（或开无痕窗口，等于干净环境）。
   - **不许用地址栏直接输入 `check.html`** —— 那是"你已经知道答案"的作弊，必须从首页点着找过去。
3. **记录第一个"找不到 / 看不懂"的地方就停下**，把它当作今天的主卡点，填入记录表。
4. 记录表里**注明这是自测（降级）**，并写明"未取得真实第三方证据" —— 完成标准里"一位真人完成核心流程"这一项**今天只能标为未达标**，不得含糊过去。

**降级不算失败**：真正的失败是"没人试、却写了通过"。表里如实标未达标，比编一条好评诚实得多。
