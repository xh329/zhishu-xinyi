# Day 11｜交互反馈实现与测试摘要

## 1. 今天的交互（页面 / 组件）

- 页面：`note.html`（写心得页 / P3）
- 组件：`#save-note`「温柔留存」按钮
- 动作：点击（或键盘 Enter / 空格）保存心得
- 数据来源：浏览器 localStorage（`store.addNote` / `store.removeNote`），不依赖后端

## 2. 状态变化（先说明，后实现）

| 状态 | 按钮 | 界面反馈 | 用户可做 |
| --- | --- | --- | --- |
| 空闲 idle | 「温柔留存」可点 | 空内容点击仍是温柔拦截 | 正常保存 |
| 收存中 busy | 禁用 +「正在收存·」加载点动画 | 按钮变浅、光标变等待 | 无需操作（防连点重复保存） |
| 已收好 done | 「已收好」深叶绿定格 | 成功提示浮现 +「先不放进去（撤销）」出现 | 1.6 秒内可撤销；否则跳转「我的心得」 |
| 收存失败 | 恢复「温柔留存」可点 | 「这一次没能收好…」失败提示 | 可直接再试一次 |

不变的：页面布局、心情多选、空内容拦截、最终跳转 `notes.html` 的行为全部保留。

## 3. 改了什么

| 文件 | 改动 |
| --- | --- |
| `note.html` | 新增撤销按钮 `#undo-save`、失败提示 `#save-fail`；成功提示加 `aria-live` |
| `js/note.js` | 保存流程改为状态机（idle → busy → done）；新增撤销回填（正文 + 心情）、失败捕获与重试 |
| `css/style.css` | 新增 `.entry.busy` 加载点动画、`.entry.done` 定格、`.undo-link`、`.fail-tip`；补 `.mood-item` / `.undo-link` 的 `:focus-visible` 焦点态 |

## 4. 四组测试（真实浏览器，agent-browser + 本地 http 服务）

| # | 测试 | 操作 | 结果 |
| --- | --- | --- | --- |
| 1 | 连点测试 | 0.6 秒内连点「温柔留存」3 次 | 只写入 1 条心得，busy 期间按钮禁用 → 无重复保存 |
| 2 | 撤销测试 | 保存成功后点「先不放进去（撤销）」 | 按钮回到「温柔留存」、正文回填、心情「平静」恢复选中、存储中该条被删除、提示「已取回，想改哪里，慢慢改。」 |
| 3 | 失败测试 | 模拟 `localStorage.setItem` 抛错（隐私模式 / 存储满） | 显示「这一次没能收好…」、按钮恢复可点、存储无新增；恢复写入后重试成功 |
| 4 | 键盘测试（余力加练） | 聚焦按钮按 Enter | Enter 保存成功；Enter 撤销成功（内容回填、心得删除） |

> 说明：测试 4 的撤销需要在「已收好」的 1.6 秒窗口内完成，命令行往返延迟会抢跑跳转，
> 因此在**测试页面内**临时把 ≥1.5 秒的定时器放大（测试脚手架，不动项目代码）以定格状态。
