## 发现真实密钥时的处置流程（红线预案）

1. **先作废，再清代码**：到签发方（CloudBase 控制台 / GitHub PAT 页面）立即重置该凭据；
   密钥一旦进过历史，删代码不等于删除泄露。
2. 重新生成新凭据，更新到 **CloudBase 控制台云函数环境变量**（或本地 `.env`），重新部署函数。
3. 清理代码中的残留并提交；若密钥在 git 历史中且仓库已公开，需评估改写历史（filter-repo）或直接视为已泄露、只走轮换。
4. 复查：重跑本清单第 1、2 项，确认为 0 条。
