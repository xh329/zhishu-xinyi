## 第三段：提示词改写（2:20–3:10）

讲三个**真实的改写**，说明"为什么改、改完拿到什么"：

| # | 最初的问法（不好） | 改成的问法（好用） | 为什么改 |
| --- | --- | --- | --- |
| 1 | 「帮我写个接口」 | 「按 `api-contract.md` §三第 1 项写 `POST /api/books`：必填校验用中文提示，重复收录走 DB 的 `UNIQUE(user_id,title)` 兜底（不是先查再插），成功回 201，SQL 全部参数化」 | 给**契约 + 边界 + 错误码**，产出才有形状可验收；"先查再插"是我明确排除的竞态写法 |
| 2 | 「重构一下后端」 | 「把 `books/index.js` 内联 SQL 原样平移到 `booksRepository.js`，接口层只留接请求/调函数/返响应；**不许改任何一条 SQL 的语义**，最后把执行过的 SQL 与原来逐字比对给我看」 | 加**可验证的验收条件**（逐字比对），重构才敢判 PASS（`outputs/Day19/regression.cjs` 就是照这句写的） |
| 3 | 「帮我看看用户会卡在哪」 | 「**不许把预测当结论**：只走页面上看得见、点得到的元素，每一步先记『外行会找什么词』，找不到就停下 —— 结论只认渲染后的 DOM，不认源码」 | 这是四周里最值钱的一句。Day 27 我对着源码断言"心迹页没有改/删入口"，实跑发现**页面上一直都有**（`components.js` 渲染出来的）——差一点照错误预测去"修"一个不存在的问题 |

**小结一句**：**提示词从"要什么"改成"要什么 + 边界是什么 + 怎么算做对了"，AI 的产出才从"能跑"变成"能验收"。**

## 第五段：平台限制（4:00–4:30）

| 限制 | 是什么 | 我怎么处理的 |
| --- | --- | --- |
| **CloudBase 环境被回收** | 专属接口域名 NXDOMAIN，Day 20–22 的「前端↔云函数↔MySQL」链路失效 | 数据层切回 `localStorage`，四视图 + 检查台**无后端也能完整跑通**；把失效如实登记 |
| **纯静态托管的固有边界** | WorkBuddy 静态托管**没有版本历史**、刷新会 404（故用 hash 路由）；数据只在各浏览器本地，**换设备/清缓存即丢** | 发布物自带**版本指纹**（页脚 + meta），让回滚可验证；做过一次实测回退（86 秒）；数据边界写入 `资源与到期说明.md` |
| **沙箱环境限制** | 无 GitHub 凭据、无云控制台登录态 | 代码改动全程可本地复跑；对外动作（发布/推送）与用户确认配合完成 |
| **课程边界** | 今日不做任何影响最终验收的新功能 | 加练项（导出按钮/完成率）**不纳入最终验收**，只在"后续优化"里排队 |
