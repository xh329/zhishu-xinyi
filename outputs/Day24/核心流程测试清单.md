# Day 24 · 核心流程测试清单（栀书心驿）

> 对应课程模板里的「打开检查台 → 读取 plan_days/checkins → 写入打卡 → 刷新确认 → 修改 → 删除」，
> 本项目没有打卡表，等价链路是：**检查台 → 读取 books/notes → 写入测试书籍 → 刷新确认 → 改写心得（PATCH）→ 删除心得（DELETE）**。
> 每一条都能一键重跑：`node outputs/Day24/regression.cjs [端口]`（结果 24/24 通过，见 `回归验证-修复后.txt`）。

## 一、链路对照表

| 课程模板 | 本项目（栀书心驿） | 检查台位置 |
| --- | --- | --- |
| 打开检查台 | 打开 `check.html` | 整页 |
| 读取 plan_days / checkins | 读取 `books` / `notes` 两张核心表 | ② |
| 写入打卡 | 写入一条测试书籍（`POST /api/books`） | ③ |
| 刷新确认 | 写入成功后自动刷新，② 条数与 ④ 更新时间跟着变 | ②/④ |
| 修改 | 改写一段心得（`PATCH /api/notes/:id`） | ⑤ |
| 删除 | 删除一段心得（`DELETE /api/notes/:id`，二次确认） | ⑥ |

## 二、测试清单（C1–C11，即 `regression.cjs` 的断言）

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| C1 | 打开检查台，等 ② 读完 books/notes | books/notes 条数出现，① 显示在线，④ 有最后更新时间 | PASS |
| C2 | ③ 单击「写入一条测试书籍」 | **恰好 1 次** `POST /api/books` → 201，反馈显示写入成功 | PASS |
| C3 | ③ 真人双击（间隔 120ms） | **仍只 1 次** POST（修复前 2 次，第 2 次 409） | PASS |
| C4 | ③ 跨秒双击（第二下落在下一秒） | **仍只 1 次** POST，且只新增 1 条书（修复前真的多插 1 条） | PASS |
| C5 | 刷新确认 | 写入触发自动刷新后 ② 条数增加（例：5 → 8） | PASS |
| C6 | ⑤ 改写正文 → 保存 | 恰好 1 次 PATCH → 200，并给出「改之前 / 改之后」对比表 | PASS |
| C7 | ⑤ 正文改成纯空白 | 前端拦下：温柔中文提示，**不发** PATCH | PASS |
| C8 | ⑤ 正文与心情都没动 | 前端拦下：「先改一处再保存」，**不发** PATCH | PASS |
| C9 | ⑥ 点「删除」→「确认删除」 | 先出二次确认行（不发请求）；确认后**恰好 1 次** DELETE，删后 GET 不再返回该条 | PASS |
| C10 | ⑥ 同一 tick 连点两次「确认删除」 | 防御性仍只 1 次 DELETE，无 404 报错 | PASS |
| C11 | 全程看控制台 | 浏览器**不再请求 /favicon.ico**；全程**零 error**；无非预期 4xx/5xx | PASS |
