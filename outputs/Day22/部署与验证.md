## 一、接口行为（对齐 api-contract.md 第 7、8 项）

### PATCH /api/notes/:id —— 改写一条心得
- 只改请求体里真的出现的字段：`content`（string，trim 后不能为空）、`mood`（字符串数组，或 null 表示清空）；其余字段一律忽略（**白名单**，不是黑名单）。
- `updated_at` 服务端自动刷新，调用方传不了。
- 成功（200）：`{ ok: true, note: { ...改后的完整记录 } }` —— 响应回读新值，前端才好做「改之前 / 改之后」对比。
- `id` 不存在 → **404** `{ ok:false, error:"not_found", message:"这段心得好像不在了，也许已经被收起。回「心迹」看看别的吧。" }`（中文说明，不假装成功）。
- 没带 id / 没有可改字段 / 字段格式不对 → 400 `invalid_param` + 中文说明。

### DELETE /api/notes/:id —— 删除一条心得
- 成功（200）：`{ ok: true, id: "n_xxx" }`。
- 按 `affectedRows` 判断真的删掉了没有：`id` 不存在（或已删过）→ **404**，同上中文说明；没带 id → 400。
- 前端安全垫：SPA 卡片点「删除」先就地换成确认行（「要把这段心得删掉吗？删掉后不可找回。」+ 留下 / 删除），见 `js/views.js` 第 251–264 行；检查台 ⑥ 同样两步确认。

**触发路径注意（Day 22 新增）**：带 `:id` 的子路径也由本函数处理。代码同时兼容
`event.pathParameters.id`（触发配成 `/api/notes/{id}` 这类带参数路径）与 URL 末尾解析

## 三、测试命令（替换 `<公网地址>` 为你的 CloudBase 触发地址）

```bash
# ① 正常改写：改正文 + 心情 → 200 { ok:true, note:{...新值...} }
curl -s -X PATCH "https://<公网地址>/api/notes/n_seed06" \
  -H "Content-Type: application/json" -H "Origin: <白名单来源>" \
  -d '{"content":"改写后的句子。","mood":["平静","轻盈"]}'

# ② 不存在的 id → 404 + 中文说明（不假装成功）
curl -s -X PATCH "https://<公网地址>/api/notes/n_不存在的id" \
  -H "Content-Type: application/json" -d '{"content":"x"}'
#  → {"ok":false,"error":"not_found","message":"这段心得好像不在了，…"}

# ③ 删除 → 200 { ok:true, id:"n_seed06" }；紧接着再删同一个 id → 404（删过又删不假装成功）
curl -s -X DELETE "https://<公网地址>/api/notes/n_seed06" -H "Origin: <白名单来源>"

# ④ 空白正文 → 400 中文「心得正文不能改成空白。」
curl -s -X PATCH "https://<公网地址>/api/notes/n_seed01" \
  -H "Content-Type: application/json" -d '{"content":"   "}'
```

## 四、数据库 SELECT 前后对比验证（核心交付）

**改之前（PATCH 前）**——先查目标行，记下原值：

```sql
-- ① 改之前：目标行原值（记下 content / mood / updated_at）
SELECT id, content, mood, user_id, created_at, updated_at
FROM notes WHERE id = 'n_seed06';
-- 期望：content='在湖边独处，才听见自己真正想要什么。'，mood='["治愈"]'，updated_at=NULL
```

**执行 PATCH**（第三节命令 ①），然后**改之后**再查同一行：

```sql
-- ② 改之后：同一行应变成新值，且只有 content / mood / updated_at 三列变了
SELECT id, content, mood, user_id, created_at, updated_at
FROM notes WHERE id = 'n_seed06';
-- 期望：content='改写后的句子。'，mood='["平静", "轻盈"]'，updated_at=当前时间
-- 对比要点：id / user_id / created_at 三列必须原样不动（PATCH 不该碰它们）
```

**删除的前后对比**——用条数 + 主键清单做双证据：

```sql
-- ③ 删之前：条数与 id 清单
SELECT COUNT(*) AS cnt FROM notes WHERE user_id = 'local';
SELECT id FROM notes WHERE user_id = 'local' ORDER BY created_at DESC;
-- 期望（种子数据）：cnt = 6，清单含 n_seed06

-- ④ 执行 DELETE（第三节命令 ③）后重查
SELECT COUNT(*) AS cnt FROM notes WHERE user_id = 'local';          -- 期望：5
SELECT id FROM notes WHERE user_id = 'local' ORDER BY created_at DESC;
SELECT * FROM notes WHERE id = 'n_seed06';                          -- 期望：Empty set（该条已消失）
```

**接口层读回闭环**（与 SELECT 交叉印证）：

```bash
# PATCH 后：GET 返回里该条 content/mood 已是新值 → 「改了 + 读回」闭环
curl -s "https://<公网地址>/api/notes?user_id=local"
# DELETE 后：GET 返回里不再有该 id → 「删了 + 查无」闭环
curl -s "https://<公网地址>/api/notes?user_id=local"
```
