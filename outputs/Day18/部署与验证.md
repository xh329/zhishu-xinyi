> 今天**不做**：PATCH/DELETE（第 4 周）、批量写入、`POST /api/notes`（Day 19 起）。

## 一、接口行为（对齐 api-contract.md 第 1 项）

| 场景 | 请求 | 响应 |
|------|------|------|
| 正常写入 | `{"title":"…新书名…"}` | **201** `{ ok:true, book:{ id, title, user_id, created_at } }`，数据库 **+1 行** |
| 重复提交（同一用户同一书名） | `{"title":"小王子"}`（已存在） | **409** `{ ok:false, error:"duplicate", message:"这本书已经在书架上了，无需重复收录" }` |
| 缺必填字段 / 空白书名 | `{}` 或 `{"title":"   "}` | **400** `{ ok:false, error:"invalid_param", message:"书名不能为空" }` |
| 其他方法（PUT/DELETE 等） | — | **405** `{ ok:false, error:"method_not_allowed" }` |

**防重复机制**：`books` 表有业务唯一约束 `UNIQUE(user_id, title)`（见 `db/schema.sql`）。重复插入时 MySQL 抛 `ER_DUP_ENTRY`(1062)，云函数捕获后转成 409 + 中文提示——数据库层兜底，接口层翻译，不靠应用层"先查再插"的竞态写法。
**服务端日志（余力加练）**：每次写入成功 / 被拒 / 校验失败都会 `console.log/warn` 一条（含 id、title、user_id），在 CloudBase 控制台「云函数 → 日志」可查，便于排查。

## 三、三条测试命令（替换 `<公网地址>` 为你的 CloudBase 触发地址）

```bash
# ① 正常写入：新书名 → 201 { ok:true, book:{...} }，数据库多一行
curl -s -X POST "https://<公网地址>/api/books" \
  -H "Content-Type: application/json" \
  -d '{"title":"Day18 验证之书（可删）"}'

# ② 重复提交：同一用户再录同一书名 → 409 duplicate，中文提示
curl -s -X POST "https://<公网地址>/api/books" \
  -H "Content-Type: application/json" \
  -d '{"title":"Day18 验证之书（可删）"}'

# ③ 缺必填字段：不传 title → 400 invalid_param，中文提示「书名不能为空」
curl -s -X POST "https://<公网地址>/api/books" \
  -H "Content-Type: application/json" \
  -d '{}'
```

## 四、数据库 select 验证 + 读回验证

```sql
-- 数据库多一行：应看到刚 POST 的那条（按时间倒序，第一行即新增行）
SELECT id, title, user_id, created_at
  FROM books
 WHERE user_id = 'local'
 ORDER BY created_at DESC
 LIMIT 5;
```

```bash
# 读回验证（本项目与 GET /api/favorites 对等的列表读取是 GET /api/books）：
# 返回的 books 数组里应包含刚写入的那本 → 「写入 + 读回」闭环成立
curl -s "https://<公网地址>/api/books?user_id=local"
```

验证完可删测试数据：`DELETE FROM books WHERE title='Day18 验证之书（可删）';`（其下若有心得会级联清理，但本条为书、无心得）。
