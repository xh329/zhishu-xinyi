## 三、最可能卡点 & 处理

### 卡点 1：跨域被拦（CORS）
- **现象**：F12 报 `CORS policy: No 'Access-Control-Allow-Origin'`，页面数据全部「数据还在路上」。
- **原因**：静态托管域名没加进云函数的 `ALLOWED_ORIGIN` 白名单；或还残留 `*` 通配符（已禁止）。
- **处理**：
  1. 确认云函数已重新部署（见第四节）；
  2. 在 CloudBase 控制台给 `books` / `notes` / `health` 三个函数都设置环境变量 `ALLOWED_ORIGIN`，值为你的静态托管地址（多个用空格或逗号分隔，例如 `https://xxx.tcloudbaseapp.com http://localhost:8080`）；
  3. 本地联调时把 `http://localhost:8080` 一并加进去。

### 卡点 2：环境变量没配 / 配错（含「整体覆盖」陷阱）
- **现象**：接口 500，或检查台「读取失败」。
- **原因**：① `DB_HOST/DB_USER/DB_PASSWORD/DB_NAME` 缺失，或 `ALLOWED_ORIGIN` 为空；② 用 CLI/API 更新环境变量时只写了新变量，**整体覆盖**导致旧变量（含数据库密码）被抹掉——这是本步最隐蔽的一个坑。
- **处理**：
  1. CloudBase 控制台 → 函数环境变量页，确认 4 个 DB 变量 + `ALLOWED_ORIGIN` 都在且生效（改完需重新部署函数让环境变量生效）；
  2. 若用 CLI，先 `tcb fn detail <函数名>` 读出存量，再与新增变量合并成一个完整 JSON 写回（具体命令见第四节 4.2）。

### 卡点 3：构建/上传报错
- **现象**：`tcb hosting deploy` 失败，或页面 404。
- **原因**：本仓库是纯静态前端（无打包步骤），直接上传根目录即可；若只传了 `js/` 漏了 `index.html` / `css/` / `check.html` 会缺页。
- **处理**：在仓库根目录执行 `tcb hosting deploy`（或控制台「静态托管 → 上传文件」选整个目录），确认 `index.html`、`check.html`、`css/style.css`、`js/*.js` 都在。

### 卡点 4（降级）：健康接口通、数据接口不通
- **现象**：检查台健康「在线」，但 books/notes 读不到。
- **处理**：优先保证首页能开 + 健康在线（满足降级底线）；数据问题记到 Day 21 处理，不阻塞今天交付。

## 四、重新部署步骤（自己本地终端执行 · 命令写法已核对官方文档）

> 核对来源：CloudBase CLI 使用指南（cloud.tencent.com/document/product/876/41539）、CloudBase CLI Functions 官方参考。
> 本机没有 tcb 时先装：`npm i -g @cloudbase/cli`，再 `tcb --version` 验证、`tcb login` 授权（无头环境会自动走设备码授权）。

### 4.1 今天只改了代码 → 用「仅更新代码」，不碰环境变量
今天只修改三个函数的 `index.js`，推荐 `code update`（只传代码，不会覆盖已配好的环境变量，最安全）：

```bash
tcb fn code update books
tcb fn code update notes
tcb fn code update health
```

等价写法是整包重传 `tcb fn deploy books / notes / health`（Day 17/18 用的就是这种）；若报「找不到函数目录」，见 4.4。

### 4.2 设置 ALLOWED_ORIGIN（跨域白名单）— ⚠️ 本步最大的坑
**通过 CLI/API 更新环境变量是「整体覆盖」**：写进去的 JSON 会替换该函数的**全部**变量。
如果只写 `ALLOWED_ORIGIN`，已有的 `DB_HOST / DB_USER / DB_PASSWORD / DB_NAME` 会被**一并抹掉**，接口立刻连不上数据库。

安全的两种做法：

- **方式 A（推荐）· 控制台改，天然增量**：云函数 → 各函数「函数配置 → 环境变量」，给 books / notes / health 三个分别加 `ALLOWED_ORIGIN`。
- **方式 B · CLI 改，先读存量再合并写回**：

```bash
# 1) 先看该函数当前有哪些变量（别 blindly 覆盖）
tcb fn detail books
# 2) 存量变量 + 新增 ALLOWED_ORIGIN 合并成完整 JSON 写回
tcb fn config update books --envVariables '{"DB_HOST":"<库地址>","DB_USER":"<账号>","DB_PASSWORD":"<密码>","DB_NAME":"<库名>","ALLOWED_ORIGIN":"https://<你的静态托管域名> http://localhost:8080"}'
# 3) notes 同样做一次；health 不连库，只需 ALLOWED_ORIGIN
tcb fn config update notes  --envVariables '{...与上面相同的一组...}'
tcb fn config update health --envVariables '{"ALLOWED_ORIGIN":"https://<你的静态托管域名> http://localhost:8080"}'
```

### 4.3 上传静态托管（纯静态，无 build）
沿用 Day 15 本机已跑通的形式：

```bash
tcb hosting deploy . / --e <环境ID>   # 在本仓库根目录执行：本地 . → 云端 /
tcb hosting deploy --help             # 不确定时先看本机 CLI 版本的参数
```

### 4.4 若报「找不到函数目录」
官方文档约定：CLI 读项目根的 `cloudbaserc.json`，**默认云函数目录是 `functions/`**，而本项目用的是 `cloudfunctions/`。
在仓库根建一个 `cloudbaserc.json` 即可（本项目此前没有此文件）：

```json
{
  "envId": "<你的环境ID>",
  "functionRoot": "./cloudfunctions",
  "functions": [
    { "name": "health", "handler": "index.main", "runtime": "Nodejs16.13" },
    { "name": "books",  "handler": "index.main", "runtime": "Nodejs16.13" },
    { "name": "notes",  "handler": "index.main", "runtime": "Nodejs16.13" }
  ]
}
```

⚠️ `runtime` 一旦创建就不可改，填错会部署失败；不确定就去控制台看现有函数实际用的运行时。

### 4.5 部署后：用 curl 直接验 CORS（比肉眼看页面更准）

```bash
# 白名单内的来源 → 应回显 Access-Control-Allow-Origin
curl -i -H "Origin: https://<你的静态托管域名>" https://zhishu-xinyi.apigw.tencentcs.com/release/api/health
# 白名单外的来源 → 应【不带】该响应头（证明 * 已失效、白名单生效）
curl -i -H "Origin: https://evil.example.com" https://zhishu-xinyi.apigw.tencentcs.com/release/api/health
```

通过标准：第一条响应含 `access-control-allow-origin: https://<你的静态托管域名>`；第二条**不含**该头。

> 注：沙箱（无头环境）无 tcb、无 CloudBase 凭据、也解析不了公网域名，故部署与真实数据截图需你在本机完成；I 端本地验证用 mock 服务（`:8787`）已走通四个视图。

## 五、环境变量清单

| 变量名 | 作用域 | 说明 | 是否密钥 |
|--------|--------|------|----------|
| `API_BASE_URL` | 前端 `js/config.js` | 公网接口基地址（已填真实值，非密钥，可入库） | 否（公开地址） |
| `ALLOWED_ORIGIN` | 云函数 books/notes/health | 跨域白名单，逗号/空格分隔，禁止 `*` | 否 |
| `DB_HOST` | 云函数 books/notes | 数据库主机 | **是**（仅环境变量，不落库） |
| `DB_USER` | 云函数 books/notes | 数据库用户名 | **是** |
| `DB_PASSWORD` | 云函数 books/notes | 数据库密码 | **是** |
| `DB_NAME` | 云函数 books/notes | 数据库名 | **是** |

> 所有密钥只在云函数侧通过 `process.env.*` 读取，前端文件与仓库中均无明文（符合 AGENTS.md [D6-5]）。
