# verify-project · 栀书心驿发布前检查

把项目**真实踩过的坑**沉淀成一份可复用检查表，一键跑出逐项 PASS/FAIL + 证据。
不是自动化流水线（本课范围外），而是**发布前手动跑一遍**的检查器。

## 怎么用

```bash
# 在项目根目录执行
node skills/verify-project/verify.cjs            # 文本报告
node skills/verify-project/verify.cjs --json      # JSON 报告（给程序读）
node skills/verify-project/verify.cjs --only 2,9  # 只跑第 2、9 项
```

退出码：**存在 FAIL = 1**，全通过 = 0。CI/脚本里可用退出码判成败。

## 检查项一览（10 项）

| # | 检查项 | 类型 | 通过标准 |
|---|--------|------|----------|
| 1 | 公网接口连通性 `/health` | 运行期 | 有后端 → 200；纯静态期标注为已知边界（不算回归） |
| 2 | 无硬编码密钥 | 静态 | `git grep` 命中 0 条（排除 `process.env.` 与注释） |
| 3 | `.env` 不入库 | 静态 | `check-ignore` 命中且无被跟踪的 `.env*` |
| 4 | CORS 不用通配符 | 静态 | 无 `Allow-Origin: '*'`，白名单来自 `ALLOWED_ORIGIN` |
| 5 | 凭据只从 `process.env` 读 | 静态 | 无字面量直赋 |
| 6 | SQL 参数化 / 无注入 | 运行期 | 复用 `outputs/Day22/regression.cjs`，55/55 |
| 7 | XSS 转义 | 静态 | `innerHTML` 插值均经 `escapeHtml` |
| 8 | 三类错误中文提示 | 运行期 | 复用 `outputs/Day23/self-check.cjs`，16/16 |
| 9 | 页面脚本引用完整（无断链） | 静态 | 每个 `*.html` 引用的 `js/*.js` 都存在 |
| 10 | favicon 已声明 | 静态 | 5 个页面都声明 `rel="icon"` |

## 判定口径（避免误报）

- **静态项（#2–#5、#7、#9、#10）**：判据黑白分明，不受网络/后端影响 —— 埋雷验证优先用这些。
- **运行期项（#1、#6、#8）**：#6/#8 走本地脚本，应稳定 PASS；
  #1 在**纯静态离线期**会失败，属**已知边界**，报告里会显式标注，不计入回归。

## 维护约定

- 新增踩坑 → 先补 `outputs/DayN/` 的证据，再在本清单加一项（写明命令/标准/证据）。
- 检查项必须**可复现**：判据不依赖人眼主观判断。
- 改了检查逻辑 → 跑 `--only` 单独验证该项，再跑全量。
